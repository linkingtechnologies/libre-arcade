# MilCity Blue 1.0.5 — AI reconstruction

There is one AI implementation, `AIPlayer`, parameterized by four levels:
- Easy (0)
- Medium (1)
- Hard (2)
- Madness (3)

They are difficulty/strategy variants of one algorithm, not four independent algorithms.

## Decision cadence
`AIPlayer.run()` executes once per second. `play()` increments a byte `turn`; build logic runs only when `turn == 1`. After `turn >= 5`, it resets to 0. Therefore build planning occurs every five AI ticks (~5 s).

## Building policy
On a build turn:
1. If `money > 20 * (buildingCount - powerPlantCount + 1)` and `energy > 6`:
   - build Commercial while `commercialCount < level*2`;
   - otherwise build level-specific military building.
2. Else, if `money > 70` and Commercial count < 2: build Commercial.
3. Else, if energy <= 6, money > 20, and Commercial count > 1: build Power Plant.
4. Else, if energy <= 0 and `(powerPlantCount*10)-buildingCount <= 0`: build Power Plant.

Level-specific military building:
- Easy: Missile Silo
- Medium: Factory
- Hard: Air Field
- Madness: Nuke Silo

Implication: commercial pre-build target is 0 / 2 / 4 / 6 for Easy / Medium / Hard / Madness under branch 1.

The historical AI never intentionally constructs House, Laboratory, or Shield Generator.

## Placement
For each build action a fresh `java.util.Random` is created. A random coordinate is selected; invalid locations are retried up to 10 times. The code then calls construction even if the final coordinate is still invalid; the factory rejects it, so the AI can waste a build opportunity but not money.

## Weapon policy
Whenever fire cooldown permits, the AI checks ammunition in fixed order and may attempt all available weapon classes in the same tick:
1. Missile
2. Mortar
3. Aircraft
4. Nuke

Each successful shot establishes a new cooldown, so later checks in the same tick normally fail until the next eligible time.

The AI never fires Spy and never deploys Shield.

## Targeting
For each shot:
- create a new `Random`;
- pick a random opponent excluding self;
- pick random x/y within 30x30;
- retry up to 10 times only while the attacker's status grid marks that cell as known WATER;
- no adjacency search, focus fire, building priority, shield reasoning, score awareness or finishing heuristic.

## Determinism
The original is not deterministic: it creates new unseeded `Random` objects for building placement, shot location and opponent selection. A faithful QA harness should therefore introduce an injectable seeded RNG only in test/oracle mode, not silently change normal gameplay semantics.
