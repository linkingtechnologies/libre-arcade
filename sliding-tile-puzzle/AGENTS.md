The ten bundled photographs are separately licensed CC BY-SA 3.0 US (JS Nature Photos); keep that attribution in `THIRD_PARTY_NOTICES.md`, `LICENSES/` and the in-game Credits dialog.
- `reference/` holds the same three archives as `../libre-jigsaw/reference/` (identical files, identical SHA-256): `puzzlegames.jar` bundles the whole 2010.08.11 Virtual Toybox Puzzle Collection, not just this one game. Keep this game's own copy rather than pointing at the sibling folder's; every game here is independent. Never edit, repack or recompress them.
- The directional-bias bug in `mix()` (original `random.nextInt(1)*2-1`, which can only ever evaluate to -1) is kept on purpose, in both the original's line and the port's `randomInt(rng, 1) * 2 - 1`. Never "fix" this to a genuine coin flip; it would silently break the shuffle-oracle match in `test/mix-parity.cjs` and stop reproducing the original game.
- `test/PrintSliderMix.java` and `test/PrintBackgroundColors.java` are executable oracles, not documentation. They were compiled with `javac --release 8` against `reference/puzzlegames.jar` and run on a Java 8 runtime; `PrintSliderMix` reaches `SliderHandler`'s private fields and its private `mix()` method via reflection rather than recompiling the class. Their output is stored in `test/fixtures/mix-oracle.json` and `test/fixtures/background-oracle.json`, which `npm test` checks against, so ordinary testing needs no JDK. If `src/game.js`'s shuffle or color math ever changes, regenerate the fixtures first:
  ```sh
  javac --release 8 -cp reference/puzzlegames.jar -d /tmp/stp-oracle test/PrintSliderMix.java test/PrintBackgroundColors.java
  java -cp "/tmp/stp-oracle;reference/puzzlegames.jar" PrintSliderMix <size> <seed>   # ; on Windows, : elsewhere
  java -cp /tmp/stp-oracle PrintBackgroundColors <r,g,b> ...
  ```
  and update the two fixture files with the new output, or restore `test/production-smoke.sh`'s original live-compile approach if a full re-verification is what's wanted instead of a fixture refresh.
- `test/photo-integrity.cjs` guards the bundled photos against later corruption using stored hashes (`test/fixtures/photo-hashes.json`), verified byte-identical to `reference/puzzlegames.jar`'s `pics/` directory when this game joined the collection. If a photo file is intentionally replaced, regenerate that fixture too.
- `public/app.bundle.js` is generated from `src/game.js`, `src/i18n.js` and `src/app.js` by `scripts/build-bundle.py` (`npm run bundle`), a plain concatenation (no import/export stripping needed, since the source files already use the classic `(function(global){...})(...)` pattern). It is committed, not gitignored: `public/` must stay immediately playable with zero build step. Never hand-edit the bundle; edit `src/` and run `npm run bundle`.
- No timer, score, move counter, hints or save/load: none are part of the recovered 2010 behavior, and none should be added.
- `npm run check` (ESLint plus the 8-file test suite in `test/run-all.cjs`) must pass before packaging and needs no JDK. `test/production-smoke.sh` remains for an optional full, live-Java re-verification (needs bash and a JDK).
- `SHA256SUMS.txt` at the game root covers every shipped file (distinct from `reference/SHA256SUMS.txt`, which covers only the three historical archives); regenerate it when any packaged file changes.
