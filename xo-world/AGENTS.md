# AGENTS.md

- Licence: **GPL-3.0-or-later**. The evidence is the "version 2 of the License, or (at your option) any later version" wording in the header of `reference/javagames-1.0/xoworld.java` (lines 1 to 19), read in a SHA-256-verified archive; see `PROVENANCE.md`. The SourceForge project page labels the project "GPLv2" without "or later"; the header is more specific and is what is followed. The restoration package had said only "GPL version 3". If it is ever changed to GPL-3.0-only, change `package.json`, `README.md`, `THIRD_PARTY_NOTICES.md` and `PROVENANCE.md` together.
- `reference/javagames-1.0/` is frozen and **CRLF**. `.gitattributes` turns line-ending normalisation off for it, otherwise a Linux checkout would no longer match `CHECKSUMS.txt`. Never reformat it. The archive's images, compiled classes and the other applets are deliberately not preserved (`SOURCE.md` says why); do not add the XO World images: their licence was never established, and the browser build must not contain them (`test/release-contract.test.js` and `test/ui-contract.test.js` enforce it).
- `src/xoworld-engine.js` and `src/game-model.js` are the engine the restoration package certified, and they are a port, not a rewrite. Keep the Serbian identifiers, the rule order and the quirks (for example `check2o3c` leaving its trial stone on the board, and both diagonals writing into the shared array `p`). `test/bundle.test.js` checks their SHA-256 values. If you must change them: change them, run `npm run test:live` against the original Java, re-record with `node tools/java-oracle.js record`, and update the two engine hashes in `test/bundle.test.js`.
- `public/xoworld-bundle.js` is generated from `src/` by `npm run bundle` and is committed. Never edit it by hand. Its first line says "M3": that is the package's name for the milestone at which the engine was certified, not a label to clean up.
- `test/fixtures/java-oracle.json` is a recording of the original Java applet. Never edit it by hand and never regenerate it to make a test pass: it is tied by SHA-256 to `xoworld.java` and to `test/java-oracle/XOWorldOracle.java`, and `node tools/java-oracle.js record` makes a new one only from a run in which the port and the original agree on every click. Run the live check first (`npm run test:live`, no recording) and read the result.
- The Java oracle needs a JDK and a display: the original extends `java.applet.Applet`, whose constructor throws `HeadlessException` on a headless JVM (use `xvfb-run` on a server). `JAVA` and `JAVAC` choose the tools; `XOWORLD_CLASS` runs the oracle on a compiled class file, for example the 2007 `xoworld.class` of the archive. The original's random fallback cannot be seeded, so the harness detects it by running sixteen copies of the original; with three or fewer empty squares that detection can be fooled, and the driver allows for it (see `specs/port-map.md`).
- This folder has its own `package.json` without `"type": "module"` on purpose: the engine, tools and tests are CommonJS, and the arcade's root `package.json` says `"type": "module"`. The `scripts/*.mjs` files are ES modules by their extension.
- The play-screen layout is measured in real browsers, not only matched against the CSS: see the 72-size sweep recorded in `CHANGELOG.md`. After touching `public/style.css` or `resizeCanvas()` in `public/app.js`, check the board is exactly square, nothing is clipped at the right edge on phone widths, and the header controls do not overlap, at several window sizes including about 390 by 844 and 1070 by 632.
- The banner "You WIN!!!" is the wording of the original's own `win.jpg`; the original's other two banners read "YOU LOSE" and "IT'S YOUR TURN...", which the port words differently on purpose. A full board shows a draw banner the original never had.
- `docs/development/` holds the restoration package's own notes and logs with their milestone labels (M2 to M8) and with the old paths (`web/`, `qa/`). Leave them as history.
