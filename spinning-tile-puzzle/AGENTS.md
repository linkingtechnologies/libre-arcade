- `reference/` holds the same three archives as `../libre-jigsaw/reference/` and `../sliding-tile-puzzle/reference/` (identical files, identical SHA-256): `puzzlegames.jar` bundles the whole 2010.08.11 Virtual Toybox Puzzle Collection, not just this one game. Keep this game's own copy rather than pointing at a sibling folder's; every game here is independent. Never edit, repack or recompress them.
- The seven-into-six no-op in `mix()` (the shuffled index list runs 0 through 6, but `spin()` only accepts 0 through 5, so index 6 is silently a no-op roughly one pass in seven) is kept on purpose, in both the original's `HexSpinnerManager.spin()` bounds check and the port's identical guard inside `spin()`. Never "fix" this by filtering index 6 out before calling `spin()`; it would silently break the shuffle-oracle match in `test/spinner-parity.cjs` and stop reproducing the original game.
- `test/PrintSpinnerOracle.java` is an executable oracle, not documentation. It was compiled with `javac --release 8` against `reference/puzzlegames.jar` and run on a Java 8 runtime; its `mix` mode reaches `SpinnerHandler`'s private `random` field and private `mix()` method via reflection, while its `spin` mode calls the public `HexSpinnerManager.spin()` directly. Its three modes' output is stored in `test/fixtures/geometry-oracle.json`, `mix-oracle.json` and `spin-oracle.json`, which `npm test` checks against, so ordinary testing needs no JDK. If `src/game.js`'s geometry, shuffle or spin math ever changes, regenerate the fixtures first:
  ```sh
  javac --release 8 -cp reference/puzzlegames.jar -d /tmp/stp-oracle test/PrintSpinnerOracle.java
  java -cp "/tmp/stp-oracle;reference/puzzlegames.jar" PrintSpinnerOracle geom <width> <height>   # ; on Windows, : elsewhere
  java -cp "/tmp/stp-oracle;reference/puzzlegames.jar" PrintSpinnerOracle mix <width> <height> <seed>
  java -cp "/tmp/stp-oracle;reference/puzzlegames.jar" PrintSpinnerOracle spin <width> <height> <vertex> <direction>
  ```
  and update the three fixture files with the new output, or run `test/production-smoke.sh` (needs bash and a JDK) for a full live re-verification instead.
- `test/photo-integrity.cjs` guards the bundled photos, thumbnails and cursor icons against later corruption using stored hashes (`test/fixtures/photo-hashes.json`), verified byte-identical to `reference/puzzlegames.jar`'s `pics/` and `images/` directories when this game joined the collection. If one of those files is intentionally replaced, regenerate that fixture too.
- `public/app.bundle.js` is generated from `src/game.js`, `src/i18n.js` and `src/app.js` by `scripts/build-bundle.py` (`npm run bundle`), a plain concatenation (no import/export stripping needed, since the source files already use the classic `(function(global){...})(...)` pattern). It is committed, not gitignored: `public/` must stay immediately playable with zero build step. Never hand-edit the bundle; edit `src/` and run `npm run bundle`.
- No timer, score, move counter, hints or save/load: none are part of the recovered 2010 behavior, and none should be added.
- `npm run check` (ESLint plus the 7-file test suite in `test/run-all.cjs`) must pass before packaging and needs no JDK. `test/production-smoke.sh` remains for an optional full, live-Java re-verification (needs bash and a JDK).
- `SHA256SUMS.txt` at the game root covers every shipped file (distinct from `reference/SHA256SUMS.txt`, which covers only the three historical archives); regenerate it when any packaged file changes.
