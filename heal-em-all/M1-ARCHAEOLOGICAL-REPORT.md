## 5. Final answers

1. **Is the original source complete?** For running the game, yes. `game.js` is exactly reproducible from its 48 CoffeeScript files (coffee-script 1.6.3, modulo CRLF), and every file the game requests exists. Missing: the compiled stylesheet (Compass output; the author's deployed CSS exists on `gh-pages`), the Quintus/stats license texts, and any record of the audio sources.
2. **Can the original run in a current browser?** Yes, unmodified: Chrome 158 headless, zero console errors, 61 fps, keyboard and touch-emulation work. It relies on remote Google Fonts and Google Analytics (both reachable only because they are online).
3. **Which mechanics were verified?** By execution: movement speed, jump, hitbox; healing by one bullet; 4 s human grace and re-infection; shooting a re-infected zombie makes a permanent dead zombie; contact damage with 1 s invincibility; zombie mode (entry, speed 140, exit on falling, second death = game over); zombie sight (350 px, same floor); the count of zombies/hearts/guns in all six levels and the random variants in levels 2-6; the summary screen with stars; menus, pause, gun and fire. The rest is source-verified only (see spec labels).
4. **Can Quintus be retained unchanged?** Yes. It needed no change to run. The one engine-related blocker (audio load errors) is handled by game-side options (`errorCallback`).
5. **Are all essential graphics legally redistributable?** Conditionally yes: declared CC BY 4.0 by the owner. Recommended: a confirmation from Paweł Madeja, because the relicensing was committed by Urbas and the 2013 terms were "all rights reserved". Not essential: `favicon.ico` (unknown origin) and the two promo images.
6. **Which audio files have unresolved licenses?** All seven sounds in both formats (14 files): collected, gun_shot, human_created, player_bg, player_hit, zombie_mode, zombie_notice. Tag hints exist for three (elevator ding; SoundBible.com; "Gut Punch 1" by CGEffects), none confirmed. They are quarantined.
7. **Suitable for static GitHub Pages?** Yes in structure (pure static files, relative URLs, no server logic). Needs C3/C4 done first (http fonts would be mixed content on https; analytics must go) and C5 (muted start) while audio is quarantined.
8. **Strictly necessary modifications:** C5 (start without audio), C3 (local fonts), C4 (remove analytics, keep a `ga` stub), C1 (stylesheet). Strongly advisable: C6 (sizing/resize), C7 (cache-busting, for offline). Everything else is optional or deferred.
9. **Can original-vs-restored be tested deterministically?** Yes, shown experimentally: manual `Q.stageGameLoop(1/60)` plus a seeded `Math.random` reproduced identical traces on the original.
10. **Principal risks:** (a) audio provenance may never be found, forcing a silent game or replaced sounds; (b) graphics confirmation from Madeja; (c) canvas text depends on font loading (visual parity); (d) window-size-dependent behaviour (bullet range, camera) is untested; (e) the old build toolchain is dead, so edits go to `game.js` or need a coffee-script 1.6.3 rebuild; (f) Safari/iOS audio and touch behaviour unknown; (g) IT localisation vs fixed-size HUD labels.
11. **Realistic effort:** about 5-8 working days for M2-M5, plus elapsed time for the rights questions (see roadmap).
12. **Still a strong candidate?** Yes. It is a complete, compact game with a distinctive mechanic, six levels, an explicit GPLv3/CC BY declaration from the owner, a clean engine, a reproducible code build and no runtime dependencies. Its only real obstacle is the audio, which can be handled with a muted release or later replacement.

## 6. Honest limits of M1

No audible-sound check, no finger-touch gameplay, no Firefox/Safari, no https hosting test, no full playthroughs. The zombie-mode "controls become active" step is unresolved (probe flaw noted in the spec). Font and Quintus license texts were not fetched. The audio web searches were quick and returned only leads, not confirmations. Parity is **not** claimed.
