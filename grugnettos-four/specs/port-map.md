# Port map

Every intelligence in the game is an adapter in `public/src/players/` behind the common contract in [`player-api.md`](player-api.md). This map links each registered player to what it was derived from, the test that checks it, and what that test actually proves. The per-player engineering notes written while porting are in [`../docs/development/PORTING_NOTES*.md`](../docs/development/); their file paths predate the `public/` layout, so read `src/...` there as `public/src/...`.

## Verification levels used here

Following the collection's verification hierarchy (see the root [`AGENTS.md`](../AGENTS.md)):

- **Level 1** — the original code is executed as an oracle and the port is compared with its output.
- **Level 2** — an independent re-expression of the original (a compact C or Python transcription, or a NumPy forward pass) is the oracle; the original itself is not run.
- **Level 3** — documented source-level review, vectors copied from the upstream's own tests, or hand-written expectations.
- **Data** — a derived data file is regenerated from the preserved source by the tool in `tools/` and compared byte-for-byte (after normalising Windows line endings).

"Re-run here" means executed in this integration environment: Windows (Node 24, Python 3.14 with NumPy and, in a scratch virtual environment, h5py; MinGW GCC 6.3 for C only), plus Debian 12 under WSL (Node 18, g++ 12.2) for the three oracles that compile the preserved C++.

The four "compact C transcription" oracles (`gnome-velena-*-native-oracle.c`, `kfourinline-native-oracle.c`) are 6 to 15 lines each and are **not** built from the preserved sources; they are a second, independent expression of the same evaluation. They catch porting slips but they are not the originals, so the Velena and KFourInLine ports are not claimed at Level 1.

## Recorded oracle output

`npm test` replays the output recorded in `test/fixtures/` by a live run, so it needs no compiler or Python. Each recording carries the SHA-256 of the inputs it answers; a changed vector set or changed weights makes the replay fail instead of passing against a stale answer. `npm run test:live` runs every oracle for real (needs `cc`/`gcc`, `g++` and `python3` with NumPy); add `CONNECTLAB_RECORD_ORACLES=1` to refresh the recordings. Nine oracles are recorded: the four C ones, GCompris and Downing (recorded on Windows), and Stratzilla, PetterS and Pons (recorded on Debian 12 under WSL with g++ 12.2 and Node 18, after a live run without recording had passed). A test whose recording is missing is reported as SKIPPED rather than passed.
