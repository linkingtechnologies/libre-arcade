# Snapping parity — Virtual Toybox 2010 vs Libre Jigsaw 2012

## Primary-source delta

`reference/puzzlegames.jar!/JigsawHandler.java` (2010.08.11) and
`reference/libre-jig-master.zip!/src/JigsawHandler.java` were compared directly.

Both generations retain the same basic neighbor gate:

- the two tiles must be true logical neighbors;
- their rotations must match;
- X and Y correction must each satisfy the strict condition `-5 < correction < 5`.

The release behavior differs after one or more external connected sets qualify.

### Original 2010

For each qualifying external group, the Java code:

1. records `groupSize * correction`;
2. translates that external group by the negative correction so it aligns with
   the dragged set;
3. merges all qualifying sets;
4. translates the merged result by the integer weighted average
   `sum(groupSize * correction) / mergedGroupSize`.

The dragged group contributes its size to the denominator and zero to the
numerator. This recenters the combined set rather than keeping either side
strictly fixed.

### Libre 2012

The changelog records the change on **2011-02-08**:

> Changed tile snap algorithm: Positions are now adjusted to the largest on-board connected group.

`JigsawHandler.mouseReleased()` stores the first/largest on-board group's
correction as `snapOffset`, leaves that anchor group in place, shifts other
qualifying groups relative to it, then moves the dragged group by `snapOffset`.

M4 implements that intent explicitly by ranking candidate connected groups by
size before choosing the anchor. Equal-size ties use deterministic current
board order.

## M4 behavior

The UI exposes `Snapping: Original 2010 / Libre 2012` independently of the
piece-cut style. This lets the geometry and snapping genealogy be tested as
separate historical axes.

Unlike M3's provisional greedy loop, M4 computes one batch of qualifying
connected sets per drop. This more closely follows the original Java
`mouseReleased()` operation and avoids recursively pulling in groups that were
not candidates at release time.

## Automated checks

`node test/snapping-smoke.mjs` verifies:

- 2010 weighted recentering with multiple connected sets;
- 2012 largest-set anchoring;
- strict 5-pixel threshold (exactly 5 does **not** snap);
- equal rotation requirement;
- de-duplication when several neighboring pieces belong to the same connected
  external group.
