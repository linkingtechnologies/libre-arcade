# Comet Pinball 1.1.0 — parity specification (M8)

## Scope

This project is a preservation-oriented HTML5 reimplementation of the original Comet Pinball 1.1.0 behavior. The preserved JAR/manual/XML under `reference/` are immutable archaeological inputs. The browser implementation is clean-room JavaScript informed by source inspection and validated numerically against deterministic traces generated by the native physics implementation embedded in the original JAR.

Parity is certified only for explicitly measured scenarios. M8 extends the deterministic full-table diagnostic contract with measured flipper/static-polygon and ball/static-polygon TOI cases, but does not claim full-game equivalence or a general/bit-identical Box2D replacement.

## M5 static-contact reconstruction retained

M6 retains the M5 sequential-impulse treatment of static polygon contacts:

- accumulated normal/tangent impulses;
- warm starting with variable-step `dtRatio`;
- six velocity iterations;
- friction clamp against accumulated normal impulse;
- polygon skin/slop and ordinary Baumgarte correction;
- two ordinary position iterations.

This remains especially important for the 30-fixture upper corner arcs.

Circular bumper contacts remain on their dedicated adaptive CCD path because that path already gives a very strong historical bumper match.

## M6 dynamic island reconstruction

M6 changes the moving flipper from a simplified moving surface into a dynamic constraint participant.

The historical island order is represented as:

1. integrate external force/gravity and the angular velocity explicitly assigned by `FlipperElement`;
2. initialize contact constraints;
3. contact warm start;
4. initialize and warm-start revolute joints;
5. six times: solve revolute-joint velocity constraints, then solve contact velocity constraints;
6. integrate positions;
7. twice: solve contact position constraints, then solve revolute-joint position constraints.

The revolute joint keeps its accumulated x/y/z impulses and limit state across frames. The dynamic contact uses both bodies' mass, COM and inertia contributions and transfers equal/opposite normal and tangent impulse to ball and flipper.

## M6 narrow TOI reconstruction

The native diagnostic exposed a second post-solver callback on frame 0 of the isolated ball/flipper scenario. Both callbacks are on flipper fixture 2 (the tapered polygon). The first carries the actual collision impulse; the second has zero reported normal impulse but a further angular/positional change.

M6 reconstructs the relevant old continuous phase with:

- TOI Baumgarte `0.75`;
- up to `20` TOI position iterations;
- no revolute-joint solve inside this narrow TOI positional pass;
- no warm-started TOI impulse.

This path is only invoked for a deep residual bullet-ball overlap with a moving flipper after the ordinary island solve. It is not a generic conservative-advancement implementation.

## M7 full-table replay contract

`specs/FULLGAME-REPLAY.md` freezes a 60 Hz three-ball deterministic input script. The historical engine produces 1,842 state frames, 532 ordered events, three plunges, three drains, two resets, and final score 45.

The current browser replay remains diagnostic rather than certified: it reaches the third drain later and scores 60. Early ball motion remains close, with about `0.001316 m` maximum position error and `0.020975 m/s` maximum velocity error over the first 90 frames.

M7 localizes two previously hidden full-table constraints:

## M8 flipper/static-corner parity

M8 reconstructs the frame-57 `flipper-left:poly` ↔ `left-flipper-corner` contact as a historical polygon/polygon constraint. The implementation follows the old Box2D 2.2.x structure needed by this table: SAT maximum separation, reference/incident edge selection, clipping, polygon skin radius, world-manifold construction, ordinary-island solving when the contact already exists, and a narrow TOI path when it is born during the sweep.

The TOI root search uses the historical target/tolerance and alternates bisection first, then secant. The TOI island has 20 position iterations, six velocity iterations, `toiBaumgarte = 0.75`, no warm start and no revolute joint.

`tests/flipper-corner.js` freezes the measured frame-57 result:

- native normal impulse: `3.575747013`; JS: `3.575741215`;
- native tangent impulse: `-0.715149283`; JS: `-0.715148224`;
- flipper-origin position error: `3.14e-8 m`;
- COM velocity error: `2.63e-6 m/s`;
- angle error: `1.19e-7 rad`;
- angular-velocity error: `7.63e-6 rad/s`.

The native/JS PostSolve counts on frames 57–61 are `1, 1, 2, 1, 2`; frames 59 and 61 contain an ordinary solve followed by a TOI solve in the same `world.step`.

Detailed native diagnostics are regenerated by `tools/oracle/run-flipper-corner-detail-oracle.sh`.

## M8 obstacle:7 circle/polygon TOI parity

Once the flipper/corner path was corrected, frame 133 remained the first material ball-velocity boundary. The isolated native oracle proves that this step is continuous/TOI: disabling continuous physics removes the contact entirely.

The historical frame-133 mini-oracle reports normal `(0.894427240, 0.447213590)`, normal impulse `0.587020755`, tangent impulse `-0.033986948`, and one begin/preSolve/postSolve sequence.

`tests/obstacle7.js` runs the JS narrow circle/polygon TOI against the same pre-step state and geometry. Current errors are approximately `7.86e-8 m` final position, `2.35e-6 m/s` final velocity and `1.99e-4 rad/s` ball angular velocity; both impulse errors are below `1e-6`.

The native diagnostic is regenerated by `tools/oracle/run-obstacle7-oracle.sh`.

## Remaining non-identical physics after M8

High-value remaining gaps include general polygon TOI beyond the two narrow reconstructed cases, exact contact feature persistence and two-point block solving, the frame-182 slingshot corner/reactive feature interaction, the earlier upper-curve phase error visible at the 1 mm / 5 mm thresholds, variable-refresh certification, and long chaotic trajectory equivalence.

The historical slingshot-force bug and original gameplay remain preserved.
