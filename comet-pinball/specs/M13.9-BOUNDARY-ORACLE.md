# Boundary oracle — reproducible procedure

`reports/M13.9-native-boundaries.csv` contains 95 one-step (1/60 s) reference states produced by the original JAR with the historical boundary fixtures, without flippers or bumpers. They cover 35 playfield-to-divider starts, 15 starts from the launch lane toward the divider, 15 legitimate passes above the divider tip, 15 central-ceiling impacts and 15 right-exterior-wall impacts. The JavaScript test uses the complete geometry; ordinary obstacles do not interfere at these starting positions, except potentially near the top boundary.

Regenerate the native trace (original JAR and JDK required):

```sh
sh tools/oracle/run-m13.9-boundary-oracle.sh /tmp/comet-m139-boundaries.csv
cmp /tmp/comet-m139-boundaries.csv reports/M13.9-native-boundaries.csv
```

Regenerate the JavaScript trace and run the tests:

```sh
node tools/m13.9-run-js-boundaries.js
node tests/m13.9-boundaries.js
```

The initial focused comparison accepted only 35 playfield-side divider starts and 15 central-ceiling starts, with position errors below 0.5 mm and velocity errors below 0.0001 m/s. These tolerances were **not** applied to the complete game or all simultaneous contacts in the launch lane. `reports/M13.9-original-js-divider.csv` records the earlier unmodified implementation; `reports/M13.9-native-divider.csv` records the first isolated native reference.
