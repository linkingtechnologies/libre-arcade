If it is ever changed (to LGPL-2.1-or-later, which the grant also allows, or to GPL-3.0-only), change `package.json`, `README.md`, `THIRD_PARTY_NOTICES.md` and `PROVENANCE.md` together.
- `reference/5ud0ku-1.8/source/` and `release/` are frozen and byte-exact (`.gitattributes` turns line-ending normalisation off; the files are mostly CRLF). Never reformat them. The archive's jar, zip and nine PNG images are deliberately not kept (`SOURCE.md` says why and how to fetch the archive again); do not add them, and do not use the images: nothing says who drew them (`test/m11-production.test.js` fails if a png, gif, jpg, jar or zip appears in `public/`).
- `public/src/core/` is a port, not a rewrite. Keep the original's names (including the misspelt `intializePencilMarks`), the order of every step, the bit-mask candidates, the two separate random streams, the ring of 100 history slots that holds 99 moves, the enumeration of a `Vector` that does not step back after a removal, and the return value of `stepBack()`, null after the last undo included. If you must change it: change it, run `npm run test:live` against the original Java, and only if it agrees re-record with `node tools/java-oracle.mjs record`.
- `test/fixtures/java-oracle.json` is a recording of the original classes. Never edit it by hand and never regenerate it to make a test pass: it is tied by SHA-256 to the ten original Java files, the four harness files in `test/java-oracle/`, `test/oracles.json` and `test/fixtures/m3-java-save-normal.hex`. `.gitattributes` keeps the hashed harness, `test/oracles.json` and `test/fixtures/` as LF on every checkout, otherwise their hashes would change with `core.autocrlf`. Run the live check first (`npm run test:live`, no recording) and read the result.
- The oracle needs a JDK (`JAVA` and `JAVAC` choose the tools; it was recorded on Java 8 and agrees on Java 21). The harness `Oracle.java` is in the original's package because the methods it needs are `protected`; `Dict`, `SudokuMidlet` and `SudokuStateControl` there are stand-ins for phone-only classes and must stay so small that they hold no game logic. The solver command follows `SolverTask`: `setAllShownDigitsAsOriginal()`, `checkForRules()`, and only then `BruteForceSolver`. Calling the solver on a grid whose given numbers clash does not terminate. The original's 15-second Hard limit is not reproduced on purpose.
- `test/oracles.json` and `test/m2-oracle.test.js` are the restoration package's records of the original (its "M2"); `docs/development/` holds the package's notes and logs with their milestone labels (M2 to M11) and old paths (`qa/`, `web/`). Leave them as history.
- The puzzle work runs in a Web Worker started with `new URL('../workers/browser-worker-entry.js', import.meta.url)` and imports with relative paths, so the game works from any folder of a static server. Keep it that way.
- The browser game takes its two 48-bit seeds from `crypto.getRandomValues`. Tests that need a fixed puzzle stub it or call the worker handler with seeds.
- The page layout was measured in real browsers at many sizes (see `CHANGELOG.md`). After touching `public/src/browser/styles.css`, check at least 320 by 568, 360 by 640, 390 by 844, 568 by 320, 812 by 375, 1024 by 501 and 1280 by 720, in English and in Italian: no scroll in either direction, a square board, and no control outside the window. Do not hide a tool button's label with `display:none`: the label is its accessible name (the rule uses a visually-hidden pattern).
- The behaviours of the original phone interface that the browser version reproduces live in `GameSession.inputDigit` (the digit entered twice, pencil mode giving way), `GameSession.reset`, `editableGrid` and `solutionViewCell`, and are mapped to `SudokuUI`, `SudokuStateControl` and `SudokuMidlet` in `specs/port-map.md`; `test/m12-original-features.test.js` pins them. While the solution is shown the page accepts no input, as the original does (`showSolution` in `public/src/browser/app.js`).
- The browser game's finishing rule is the original's (`isFinished` in `public/src/browser/app.js`: full and valid), not "equal to the stored answer".
- `test/m8-worker.test.js` runs the 17-given Hard fixture in a worker; it takes about 5 seconds on a quiet machine and its limit is 120 seconds on purpose.
