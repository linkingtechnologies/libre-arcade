# AGENTS.md

- Licence: **GPL-3.0-only**, not GPL-3.0-or-later. The headers of `reference/bomber-1.0/src/Bomber.java` and `GameCanvasBomber.java` say "the Free Software Foundation, version 3 of the License." and nothing about later versions, and `test/production.test.mjs` fails if either gains or is read as having an "or later". Same finding as the collection's Memonix games. See `PROVENANCE.md`.
- `reference/bomber-1.0/` is frozen: the two Java files are CRLF and `.gitattributes` turns line-ending normalisation off for them, otherwise a Linux checkout would no longer match `CHECKSUMS.txt`. Never reformat them. The archive's PNG resources, jar and compiled classes are deliberately not preserved (`SOURCE.md` says why): do not add the PNGs, their licence was never established and `test/production.test.mjs` fails if an image, jar, class or zip appears in `public/`.
- The game state in `public/src/game-state.js` is a port of one loop, and the port keeps its quirks: heights can go to -1, an impact destroys up to three blocks without re-checking, `landings * 3 + 8` bounds the new city's heights, caps are drawn only for heights above 4, and the random draws happen in the original's order (height, cap if tall, colour, per building; 30 plane frames per crash). Do not "fix" any of it. `test/java-oracle.test.mjs` fails on any change in behaviour.
- `test/fixtures/java-oracle.json` is a recording of the original loop. Never edit it by hand and never regenerate it to make a test pass: it is tied by SHA-256 to `GameCanvasBomber.java` and to `test/java-oracle/BomberOracle.java`. Run the live check first (`npm run test:live`, which records nothing) and read the result; `node tools/java-oracle.mjs record` writes a new recording only from a run in which the port and the original agree on every iteration.
- The oracle relies on a trick: `test/java-oracle/Thread.java` is a class named `Thread` in the unnamed package, which shadows `java.lang.Thread` for the original (also in the unnamed package), so its sleeps become virtual. Do not move the stand-ins into a package and do not add an `import java.lang.Thread`. The MIDP stand-ins in `test/java-oracle/javax/` implement only what the original calls; they are not a MIDP emulator. The original's one private field, `appStatus`, is read by reflection. `Graphics.drawImage` in the stand-in must stay `void`: the original's compiled class calls it with that descriptor. With `BOMBER_CLASS` the oracle runs the archive's compiled class instead of the source build, after `redirectThread()` has rewritten its `java.lang.Thread` reference in memory (see `specs/port-map.md`); the class itself is not kept in the repository.
- The oracle's known and documented difference (the motor tone the original plays after a landing, which the port does not) is normalised in `normaliseOriginal()` in `tools/java-oracle.mjs`. If another difference ever appears, find out which side is right before widening that function.
- `test/java-oracle/*.java` is pinned to LF in `.gitattributes` because the harness is hashed into the recording; keep it that way.
- `app.js` exposes `window.__bomber` only with `?qa=1` or `?seed=`, for automated browser tests. The ticks use a fixed 141 ms timer. A press is latched until the next tick (`latched` in `app.js`), so a tap shorter than a tick still drops a bomb: a deliberate, maintainer-approved difference from the original, whose first `getKeyStates()` call per turn discards latched presses and loses short taps (see `specs/port-map.md`). Do not remove the latch as a "fix" for fidelity, and do not move this logic into `game-state.js`: the keys are the oracle's input and the game rules must stay what the original does.
- `public/` runs as native ES modules with no build step; `npm run build` only copies it to `game/`. Browser files live in `public/`; tests, tools, `reference/`, `docs/` and `specs/` stay at the root.
- `docs/development/` holds the restoration package's own notes (a prose list of the original's rules and a changelog). Leave them as history.
- The origin of the archive is the SourceForge project `bomberj2me` (`https://sourceforge.net/projects/bomberj2me/`, maintainer account `yomboprime`, `Bomber.zip` released 2008-12-22 in a folder called "Bomber 1.0"); SourceForge publishes no checksum, but the package's `Bomber.zip` was downloaded again on 11 October 2026 and is byte for byte the same file (SHA-256 `274c78e5…`), so it is the SourceForge download. The unrelated SourceForge project `j2mebomber` is a port of While True's Nokia game: do not cite it. The SourceForge page labels the licence GPLv2 while the files say version 3 (see `PROVENANCE.md`): the files win.
