# Provenance

Concentration Room is a **ported** game: the rules, the random number generator and the deal, the frame state machine, the CPU player, the pad model, the story tables and the sound data are a JavaScript port of the 6502 assembly of Concentration Room 0.02, a game for the Nintendo Entertainment System. The pages, dialogs, languages, saved preferences and drawing code around them are new. The original sources and the release ROM are preserved in [`reference/ConcentrationRoom-0.02/`](reference/ConcentrationRoom-0.02/SOURCE.md); the mapping and the evidence for each part are in [`specs/port-map.md`](specs/port-map.md).

## Licence: GPL-3.0-or-later, from the headers and the author's page

Two kinds of evidence, both read in the archive and not assumed:

- **Headers.** `aidiocy.s`, `drawcards.s`, `litemain.s`, `liteopponents.s`, `litetitle.s`, `memorygame.s`, `shuffle.s`, `music.s` and `sound.s` say "either version 3 of the License, or (at your option) any later version". These are the files the port is made from.
- **The author's page.** The "Legal" section of `README.html` says "the accompanying program is free software: you can redistribute it and/or modify it under the terms of the GNU General Public License, version 3 or later", and adds: "As a special exception, you may copy and distribute exact copies of the program, as published by Damian Yerrick, in iNES or UNIF executable form without source code."

`GPLv3.txt` in the archive is the licence text; `LICENSE` here is the full GPL v3 text. The other files of the archive (`bcd.s`, `pads.s`, `unpkb.s`, `musicseq.s`, the headers, the makefile, the linker script, the Python tools) carry the all-permissive notice "Copying and distribution of this file, with or without modification, are permitted in any medium without royalty provided the copyright notice and this notice are preserved".

The exception is why the unmodified ROM is kept next to the sources. The port itself is GPL-3.0-or-later, which the grant above permits.

### A caveat that is not settled: the lettering

The same `README.html` says that the font of the game's logo is "Wasted Collection", and that the monospace font of the menus "originally appeared in the 'Who's Cuter' demo and is based on Apple Chicago by Susan Kare". The archive gives no separate licence for either design, and the two tile atlases contain bitmap letters drawn from them; the game cannot draw its menus without those tiles. No font file is redistributed. Whether the bitmap letters carry any right beyond the author's own GPL grant is not established here. If it matters, the atlases are the files to replace (`public/assets/original/`, `THIRD_PARTY_NOTICES.md`).

## Where the files come from

- **The archive.** It was supplied inside the restoration package as `reference/ConcentrationRoom-0.02.zip` with the SHA-256 above. The 39 files inside were extracted and hashed; the package's own list of hashes agrees, and every file kept here is byte for byte the archive's (`test/reference.test.js` checks it on every run).
- **Its origin.** The project page <https://pineight.com/croom/> offers the archive at <https://pineight.com/croom/ConcentrationRoom-0.02.zip>. **It is byte for byte the file the author serves.** It was downloaded from that address on 11 October 2026 (HTTP 200, `Content-Length: 100162`, `Last-Modified: Fri, 17 Aug 2018 00:34:43 GMT`) into a folder outside the repository: 100,162 bytes, SHA-256 `0e9773924b5d8b53d727f3359b62f3730ec95f139d64242236cb9ec28f871566`, the same as the archive supplied in the package. The Internet Archive's snapshot of 15 September 2026 of the same address reports the same size. `reference/ConcentrationRoom-0.02/SOURCE.md` gives the command to fetch and compare it again.
- **The author's repository.** <https://github.com/pinobatch/croom-nes> begins with a commit of 19 November 2016, `8cad6d65a0ddff7f9ec9b1fc38a89bcfe3ff43f6`, "import 0.02 + terriblegate fix". Its patch, read on 11 October 2026, adds a `croom.nes` of the same size as ours and the sources, and moves a `PPUCTRL` write in `blitCardSprites` ahead of the sprite upload, a hardware detail (the "Terriblegate" fix) that touches no rule. The release ROM that this repository runs predates it. The restoration package's `BASELINE.md` says a comparison of Git blobs found the 0.02 files identical to that import except four; that comparison was not repeated here, and the files after the first commit were not compared.
- **What the archive is.** The sources of the game (`memorygame.s`, `aidiocy.s`, `shuffle.s`, `drawcards.s`, `litemain.s`, `litetitle.s`, `liteopponents.s`, `pads.s`, `sound.s`, `music.s`, `musicseq.s`, `unpkb.s`, `bcd.s` and the headers), two packed tables, four Python tools, the makefile and linker script, the README page, the author's diary and to-do list, two tile atlases, three documentation images and the release ROM.

## What was checked independently

- **The original ROM was run, not only read.** `tools/rom-oracle.mjs` runs the preserved `croom.nes` from reset on a minimal NES (`tools/nes-machine.mjs` over the 6502 core `tools/mos6502.mjs`), steers it through the title menu with a scripted player, and plays each game with seeded input. The port plays the same game: it takes the generator bytes and the frame counter the ROM mixed into its seed when it dealt, deals, and is then fed the same pad bits once per iteration of the original's main loop. At the start of every iteration the ROM's RAM is compared with the port's state. This is the collection's Level 1, an executable oracle. The numbers, the scenarios and the limits are in [`specs/port-map.md`](specs/port-map.md).
- **It found differences the source text did not show.** The release was built with the author's `shuffle.py -r`, which runs `.shuffle` blocks in the reverse of their written order. The delivered port had been written from the text of the source; the oracle found several places where the ROM does something else (the order of the four direction handlers, the one direction skipped while a controller is being passed, the missing check of whose turn it is for movement and the B button, the CPU player clearing pad 1's new presses, the CPU's turn starting at once in Vs. CPU, a cleared table falling through into the next handler, and a timer left at 255 at the end of a game). All are fixed in the port and listed in `CHANGELOG.md`.
- **The pictures are the ROM's.** `tools/nes-frame.mjs` composes from the minimal NES's memory the picture the ROM would put on the screen, and the page's own renderers are run in Node (`tools/canvas-shim.mjs`) and compared with it pixel by pixel: the game screen at every iteration of the ROM oracle's scenarios (119,426 frames of the 64 scenarios), the title's two menus (with the arrow on every line), 14 opponent scenes and the three opening and instruction texts at 14 moments of their scroll and fade. The first comparison found thirteen differences in the package's drawing (the list is in `specs/port-map.md`; the first was a background that the page did not scroll by the 12 pixels that the ROM does, which put the emblems of open cards above their cards). All are fixed. What is not compared is in the limits there.
- **The data is the ROM's.** `test/rom-data.test.js` looks for the port's tables in the ROM's program, byte for byte: every line of the English story, opponents and instruction text (90 lines, and the opening text in the same order), the ten-stage story table (80 bytes), the eleven sound effects, the five music patterns, the two conductors and the instrument table, the five layouts of the table and the palettes of the cards and of the table. All are there. That check found one transcription error in the package's audio data: the last two notes of the intro's bass line were quarter notes where the ROM (and the source) have dotted quarters. It is fixed.
- **The 6502 core is tested on its own.** `test/mos6502.test.js` checks addition, subtraction and comparison for every accumulator, operand and carry against their definitions, and the addressing modes, stack, branches, the indirect-jump page bug and the interrupt sequence against hand-written programs.

## What the package claimed that could not be checked or was not so

- **"Behavioral oracle", with "frozen deal vectors".** Its `BEHAVIORAL-ORACLE.md` lists five boards "for each independent deal" from a reset seed with chosen frame counters. Where those numbers come from is not stated (nothing says they were taken from the ROM); the oracle above compares the boards the ROM itself deals, in every scenario. The five vectors are kept as tests.
- **A parity checklist with every row "PASS".** The rows the oracle can see (the timings, the repeat, the order in which the two pads are scanned, the miss budgets, the turn rules, the CPU's use of the generator) agree with the ROM; the differences found were in behaviour that the checklist has no row for (the direction order, the pad's use during the computer's turn, the end of a cleared table; see above). The rows about the pictures ("source-derived") were not what the ROM draws in thirteen places, found only when the pictures were compared with the ROM's (see above). The row about the sound ("synthesised from source data") is at a lower level of evidence: the sound data are now compared with the ROM's bytes, but how the page turns them into sound is not compared with anything, because no sound chip is modelled.
- **A visual-parity test against its own picture.** The package's test compared the drawn board with a picture that its own Python script made (`board-oracle.png`), pinned by hash. That picture had the same errors as the drawing (no scroll, two swapped tile pairs), so the test could not see them; it is gone, replaced by the comparison with the ROM's pictures.
- **"Automated Chromium screenshot certification is not claimed".** True of the package; this integration checked the pages in real browsers (see `CHANGELOG.md`).
- **The Terriblegate patch.** `docs/development/post-release-2016-terriblegate.patch` is, in its own words, a reconstruction of the one change. The real commit says the same in substance.
- **A clean rebuild.** The package says `ca65` and `ld65` were not available; they are not here either, and at least one of the Python helpers uses Python 2 era calls. The release ROM could not be rebuilt from the sources, so the ROM and the sources are tied only by the author's release and by the checks above (the English text of the sources is in the ROM; the behaviour of the ROM matches the port).
