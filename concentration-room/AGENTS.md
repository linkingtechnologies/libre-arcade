# AGENTS.md

- Licence: **GPL-3.0-or-later**. The evidence for the original is the "Legal" section of the archive's `README.html` ("version 3 or later") and the header of nine of its assembly files ("either version 3 of the License, or (at your option) any later version"); the other files carry an all-permissive notice. The author's special exception (exact copies of the program in iNES or UNIF form without source) is what allows the release ROM to be kept in `reference/`. See `PROVENANCE.md`. If the licence is ever changed, change `package.json`, `README.md`, `THIRD_PARTY_NOTICES.md` and `PROVENANCE.md` together.
- `reference/ConcentrationRoom-0.02/source/` and `release/` are frozen and byte-exact (`.gitattributes` turns line-ending normalisation off for them). Never reformat them and never add to them: `test/reference.test.js` fails when a kept file changes or an unlisted one appears. The archive's zip and the three illustrations of the author's documentation are deliberately not kept (`reference/ConcentrationRoom-0.02/SOURCE.md` says why and how to fetch the archive again). The two tile atlases in `public/assets/original/` are the archive's own files, byte for byte; the test checks that too.
- **Where the source text and the ROM disagree, the ROM is right.** The release was built with `shufflemode = -r`: the author's `tools/shuffle.py` runs each `.shuffle` block in the reverse of its written order. The direction handlers of `memorygame.s` therefore run Right, Down, Left, Up, and only Right is skipped while the controller is being passed. `public/src/frame-input.js` reproduces that, with the reasons in its comments. Do not "fix" the order to match the text of the source.
- `public/src/` is a transcription, not a redesign. Keep one iteration of the original's main loop as one frame (`FrameGame.tick`, `applyHistoricalGameInputFrame`); keep the CRC-style generator and the deal that is not a Fisher-Yates shuffle; keep the single generator shared by the deal, the CPU player and the B button; keep the stale variables the original leaves behind (for example `stateTimer` wrapping to 255 at the end of a game, the collecting velocities that are never cleared) unless the oracle shows they do not matter. Replacing a frame count with a timer, or "tidying" a quirk, makes the oracle fail.
- **Run the ROM oracle after any change to the game logic.** `npm test` replays the quick scenarios (the ROM is run from reset on `tools/nes-machine.mjs`); `npm run test:live` replays all 64 and takes several minutes. `test/fixtures/rom-oracle.json` holds the scenario plan, the RAM address of each compared field and the totals; it is tied to the ROM by SHA-256. Never edit it by hand and never record it again to make a test pass: run the live check first and read the first difference (it names the field, the game and the iteration). Record again only when the port is right and the plan has to change: `node tools/rom-oracle.mjs record --games 64 --seed 20100718`, which refuses to write unless every scenario agrees and every field has exactly one address. It takes about 20 minutes on four cores.
- `tools/mos6502.mjs` and `tools/nes-machine.mjs` are the oracle's world, not general emulators: a 6502 core with cycle counts (151 documented opcodes, tested exhaustively for the arithmetic in `test/mos6502.test.js`) and a NES that has the ports and the memory the ROM touches and draws nothing. If the oracle ever stops at an instruction or a register the machine does not know, extend the machine and test the new instruction; do not skip it.
- The ROM's variables sit where the author's shuffling put them. `tools/rom-oracle.mjs` finds the few addresses it needs by their code (frame counter, generator bytes, `read_pads`, the two seed-mixing sites) and the rest by elimination across all scenarios. Do not hard-code an address from the symbol listing of the source.
- The English text of the story, the opponents and the instruction screens is the original's and `test/rom-data.test.js` finds every line of it in the ROM. The Italian text is a translation made for Libre Arcade; keep the two tables in step (same number of rows, same markers).
- Player-visible text carries no development vocabulary (`test/production-ready.test.js` fails on "oracle", "PRNG", "SHA-256" and the like in `index.html`). The notes for developers are in the documents of the repository, not in the page.
- **What the page draws is compared with what the ROM draws.** `tools/nes-frame.mjs` composes the ROM's picture from the minimal NES's memory (nametable, attributes, palettes, scroll, sprites), `tools/canvas-shim.mjs` lets the page's renderers (`renderer.js`, `title-renderer.js`, `story-renderer.js`) run in Node, and `tools/render-oracle.mjs` plays the ROM oracle's scenarios and compares the two pictures at every iteration. `npm test` runs the quick ones (`test/render-oracle.test.js`, `render-title.test.js`, `render-story.test.js`); after touching a renderer, `nes-visual.js` or `story-presentation.js`, run `npm run test:render` (about ten minutes). A difference names the scenario, the iteration and the region, and `--out DIR` saves the ROM's picture, the port's and the difference side by side. Do not draw by eye what the ROM draws: a background that was not scrolled by 12 pixels and tiles swapped in pairs looked right to a reader of the source.
- The pictures in `public/assets/derived/` (the title, the five opponents, the Hombon logo) are frames that the ROM draws, made by `tools/render-assets.mjs`; `node tools/render-assets.mjs --check` compares the files with a new run of the ROM, and their digests are pinned in `test/story-presentation.test.js` and `test/title-menu.test.js`. Do not edit them or draw replacements; run the tool.
- The page layout was measured in a real browser at many sizes (see `CHANGELOG.md`). After touching the CSS in `public/index.html` or `public/src/viewport.js`, check at least 320 by 568, 360 by 640, 390 by 844, 568 by 320, 812 by 375, 1024 by 600 and 1280 by 800, in English and in Italian, in the title, the dialogs, the instruction scene and a game: no scroll in either direction, a canvas of the NES's proportions (256 by 240), no control outside the window.
- The game reads the keys once per frame on a `requestAnimationFrame` clock, so it does not advance in a hidden tab. In a test, hold a key for at least one frame (about 17 ms), and run the page in a window that is shown.
- `docs/development/` holds the restoration package's own notes, test report and manifest, with its milestone labels and old paths (`/reference`, `assets/`). Leave them as history; the facts of this integration are in `PROVENANCE.md`, `specs/port-map.md` and `CHANGELOG.md`.
