## The license is GPL-3.0-only, not GPL-3.0-or-later

Same finding as this collection's other two Memonix restorations ([`memonix-mosaic/`](../memonix-mosaic/), [`memonix-builder/`](../memonix-builder/)): the recovered `reference/Memonix-License.txt` names "the GNU General Public License version 3" with no "or later" language, and the same wording repeats in the per-file C++ headers across the recovered source tree. A fresh search of this delivered package found no "or later" phrasing anywhere outside the generic FSF boilerplate. Per this collection's own rule (see the root [`AGENTS.md`](../AGENTS.md)), the port stays **GPL-3.0-only**.

## Independent verification

Every recovered asset was independently re-derived from the original binary formats, reusing the same from-scratch VFS/RLE/BMP/PNG pipeline built for `memonix-mosaic/` and `memonix-builder/` — not the delivered package's own extraction claims. `gamedata.vfs` did not need re-extracting: its SHA-256 is identical to the copy already verified for Builder, and that extraction already contains every file this game needs (`DATA/PAIR/*`, `DATA/pr_p.bmp`, and the shared `DATA/mainmenu.jpg`/`DATA/main_game.bmp`/`DATA/game2.bmp`/`DATA/start*.jpg`/`DATA/box.jpg`/`DATA/BUILDER/0.bmp` already pulled out for the other two games). The four C++ source files this game's logic depends on (`game_start.cpp`, `game.cpp`, `options.cpp`, `Main.cpp`) were also confirmed byte-identical, by SHA-256, to the already-extracted source tree, against the hashes `reference/SOURCE_SHA256.txt` itself records for each file.

Cross-checking found:
- all 72 Pair card PNGs (card back + 71 toy faces) pixel-identical to their recovered BMP source (294,912 total pixels checked, zero mismatches);
- `pr_p.bmp` → `pair-preview.png` and `game2.bmp` → `game2.png` pixel-identical (lossless container change only);
- `main_game.bmp` → `mode-hover-frame.png` pixel-identical once accounting for the documented black-colour-key-to-alpha conversion;
- `blank-cell.png` pixel-identical to `BUILDER/0.bmp` (confirming the cross-game asset reuse documented in `THIRD_PARTY_NOTICES.md` is exactly what it claims to be, not a different image that happens to look similar);
- `mainmenu.jpg`, `start.jpg`, `start2.jpg`, `start3.jpg`, `game.jpg` and `box.jpg` all byte-identical between the recovered archive and the distributed copies.

This is level-1 (executable-oracle-equivalent) verification for every redistributed asset.

The gameplay logic was read directly from the verified source files rather than taken from the delivered documentation on trust. `game_start.cpp`'s face-selection loop (`test = StartNum + fmod(rand(),71)`, rejected on duplicate) and its two placement loops (4-copy for D0 on boards larger than 2×2, 2-copy otherwise, each placing by repeatedly re-rolling a random `(X,Y)` until an empty cell is found — confirmed **not** Fisher-Yates, exactly as `docs/BEHAVIOR_ORACLE.md` states) match `public/src/model.js`'s `generatePair` directly. `game.cpp`'s click-handling block (`SearchFor` tracks the first flipped card; a second matching card sets `RightShow` and, after the historical 500 ms delay, clears both cells to `-1`; a second mismatching card sets `ErrorShow` and, after the same 500 ms delay, hides every currently-flipped cell — and, only when `Setup.Difficult==2`, additionally restores `FieldData` from the `FieldDataPair` backup taken at generation time, bringing every previously-completed pair back into play) matches `public/src/model.js`'s `clickCard`/`resolvePending` directly. The port's Hard-mode restore is implemented differently at the code level — it resets every board cell's visibility status to `'hidden'` rather than copying from a separate backup array — but this is a faithful JS-idiomatic equivalent: the port's `board` array is never mutated to a "completed" sentinel the way the C++ `FieldData` is set to `-1`, so resetting status achieves the identical observable effect without needing its own backup copy.

This is strong level-3 (documented, line-by-line source-level equivalence review) verification, not level-1 — no C++ toolchain was available in this environment to build and run the original executable as a live oracle for gameplay — but it reads the actual decision logic rather than relying on the delivered behavioral-oracle document's own description of it.
