- The 72 Pair card PNGs (`public/assets/pair/`) and most UI assets (`public/assets/ui/original/`) came from the same `gamedata.vfs` already extracted for `../memonix-builder/` — no VFS extraction was re-run for this game. If an asset ever needs regenerating, extract it from `../memonix-builder/reference/memonix_1.6_src.tar.bz2`'s `gamedata.vfs` (same archive here, same SHA-256) using the VFS/RLE algorithm described in `PROVENANCE.md`/`specs/port-map.md`, and re-verify against `docs/pair-png-manifest.csv` / `public/assets/ui/original/menu-asset-manifest.json`, not against the currently-committed PNGs.
- `blank-cell.png` is intentionally a copy of Builder's `BUILDER/0.bmp` blank tile, not a Pair-specific asset — this is a genuine cross-game asset reuse in the original archive, not a mistake. See `SOFTWARE_ARCHAEOLOGY.md`.
- The 71-face pool (`FACE_IDS` in `public/src/assets.js`) deliberately has no `toys-015` entry. Never "complete" it to 72 faces — the historical archive never shipped that file, and the original game's face-selection arithmetic works precisely because the loaded textures are 71 contiguous IDs, not 72 with a hole. See `docs/SOURCE_MAP.md` and `SOFTWARE_ARCHAEOLOGY.md`.
- `public/src/model.js`'s `generatePair` placement loop (`while(left){const x=...,y=...;if(board[x][y]===null){...}}`) is a line-by-line transcription of `game_start.cpp`'s reject-and-retry placement — it is rejection sampling, not a shuffle, and is slower on a nearly-full board by design of the original, not a performance bug to optimize away.
- The Hard-difficulty full-board reset on any mismatch (every previously-completed pair returns to play, not just the two just-flipped cards) is a verified, deliberate historical mechanic, not a port overcorrection — see `PROVENANCE.md`'s line-by-line comparison against `game.cpp`. Never soften this to "only reset the two mismatched cards" on difficulty 2.
- `public/` runs as native ES modules (`<script type="module" src="src/app.js">`) with zero bundler and zero build step. Do not introduce one; `npm run build` only copies `public/` to `game/` verbatim.
- `tests/production.test.mjs` originally computed its root directory with `path.resolve(new URL('..',import.meta.url).pathname)`, the same Windows drive-letter-doubling bug found and fixed in `../memonix-builder/`. It was fixed here too, to `fileURLToPath(new URL('..',import.meta.url))`. `tests/release.test.mjs` already used the correct pattern as delivered.
- Tests live in `tests/*.test.mjs`; `npm test` runs `node --test tests/*.test.mjs`. Every test file resolves game assets under `public/` and non-game files (`reference/`, `docs/`, `LICENSE`, etc.) at the game root — keep that split when adding tests.
- `docs/BEHAVIOR_ORACLE.md`, `docs/GAMEPLAY_PARITY.md`, `docs/SOURCE_MAP.md`, `docs/ASSET_AUDIT.md`, `docs/MENU_FIDELITY.md`, `docs/VISUAL_PARITY.md`, `docs/difficulty-matrix.csv`, `docs/pair-assets-manifest.csv` and `docs/pair-png-manifest.csv` were delivered already accurate and cross-checked against independent verification; keep them as the primary parity/audit trail rather than duplicating their content elsewhere.
- The title screen's four 128×128 mode-selector windows are historical Memonix coordinates (`public/src/menu_layout.js`), identical to `../memonix-mosaic/`'s and `../memonix-builder/`'s — see `docs/MENU_FIDELITY.md` and `SOFTWARE_ARCHAEOLOGY.md`. Only Pair's own window (at `(496,66)`) is historically accurate to its original purpose; the other three are relabeled Instructions/Options/Credits because Pair never shipped as a standalone title.
